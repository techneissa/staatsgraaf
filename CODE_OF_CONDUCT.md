# Code of conduct

Staatsgraaf is a public-interest project about the Dutch state. It does not accept pull requests or other contributions. This code still applies to issues and any other project space.

## Expected behavior

- Be accurate. Back a claim about the data or the code with a source, a test, or a reproducible step.
- Be direct and civil. Critique the work, not the person.
- Assume good faith, and ask a question before you assign a motive.
- Respect the scope of the project. It stays neutral about politics; it documents the structure of government and the sources for it.
- Respect privacy. The dataset covers people in a public function only. Do not add contact details, private addresses, family data, or anything the government has not published.
- Accept a correction. A named gap or a logged correction is a normal part of the work.

## Unacceptable behavior

- Harassment, insults, threats, or discrimination of any kind.
- Publishing someone's private information without their consent.
- Using the project to target or pressure an official, or to push a political position.
- Deliberately introducing an unsourced fact, or removing a source to hide one.
- Deliberately bypassing a source's terms, a rate limit, or a paywall.
- Sustained disruption of a discussion, or bad-faith argument after a decision is made.

## Scope

This code applies in every project space and when someone represents the project in public. It does not cover private conversations that have nothing to do with the project.

## Reporting and enforcement

A report goes to the maintainer. The project does not yet publish a contact address, so there is no public channel today. That is a named gap. Once an address exists, it is the reporting path and the maintainer will keep a report confidential.

The maintainer will review a report, may ask for more detail, and can warn, remove a contribution, or block a person from the project. The response matches the behavior: a single careless remark is handled with a note, while harassment or a deliberate data violation is not.

The maintainer holds the same standard as everyone else. A decision is recorded where a later contributor can find it, not left in a private thread.
